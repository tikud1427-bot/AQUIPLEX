# Patch 2026-10-08 — E8: decision questions get the World Model they depend on

Built on your latest upload (the 10-07 patch). As before, run `./apply-deletions.sh` after extracting, because the two `before-pr` snapshot files came back.

## The problem, measured on live Postgres

"What should I focus on next?" and "Should I launch this week?" mention no goal, blocker or deadline, yet the answer depends on all three. The context for these questions contained the goal at best and never the blocker. The cause was three defects in the slot engine, all in `brain/contextEngine/`:

1. **Wrong template.** The chat classifier labels both questions `simple_qa`. That fell through to the one-slot `conversation` template, so the blueprint's own flagship question never got a goal, deadline or blocker slot.
2. **Slots could never be filled by the World Model.** A slot was filled when a candidate's `kind` matched it (`blocker`, `goal`, `time`). No producer in the codebase emits those kinds; every canonical claim arrives as `kind: 'fact'`.
3. **"Filled" didn't mean known.** Round two appended the slot word to the question ("… blocker") and stamped that slot onto **every** item the text search returned, both in `e8Pipeline` and in the canonical retriever. So a sentence merely containing "blocker" made the answer read SUFFICIENT.

## Fix

- **Slots are defined by canonical predicates.** For example, `blockers` → `blocks`/`blocked_by`, `goal` → `plans_to`/`builds`, `deadline` → `deadline_for`, `prior_plans` → `decided`/`rejected`. A claim fills a slot by its predicate. Slots with no predicate (constraints, risk) keep their old behaviour, and no predicate was invented for them.
- **Slot lane.** Required slots are fetched by the predicates that define them: one owner-scoped, bounded `structuredClaims` query. It is reported under the existing `structured` lane, so ablation and rank fusion count it as structured evidence; no new, unevaluated lane was added (L14).
- **Honest stamping.** Round two and the canonical retriever attach a slot only to items whose predicate fits it. Text hits are still kept as context; they just no longer count as evidence.
- **Decision form.** "should I/we…", "what should I focus on/do/prioritise…", "where should we start", "what's my next step" now get the decision scaffold when the classifier's label is generic. A specific label (planning, coding, …) is never overridden.
- **PARTIAL vs UNKNOWN.** When some required slots are known, the model is now told PARTIAL: answer from what is known, name the gap without guessing, and ask about it at most once. Before, the text said UNKNOWN, which pushes the model to refuse — the interrogator failure Blueprint E8 warns about. UNKNOWN is kept for when no required slot is known. The machine-readable state (`epistemicState`, `shouldAbstain`) is unchanged.

## Result on live Postgres

These are the actual context blocks the model now receives:

```
Q: What should I focus on next?            (classifier: simple_qa)
EVIDENCE STATUS: PARTIAL — answer from what is known below.
Not known: deadline. Say so plainly; do not infer or fabricate it. If it changes the answer, ask about it once.
• I am building AQUIPLEX {slots: goal}
• Reliability is blocking the launch {slots: blockers}
• I want to launch AQUIPLEX in November {slots: goal}

…after the user says "The launch deadline is November 15":
Q: Should I launch this week?
EVIDENCE STATUS: SUFFICIENT for the required QueryPlan slots.
• The launch deadline is November 15 {slots: deadline}
• Reliability is blocking the launch {slots: blockers}
• I want to launch AQUIPLEX in November {slots: goal}
```
