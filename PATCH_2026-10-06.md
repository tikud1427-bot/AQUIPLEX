## One decision left for you (kept, not changed)
`POST /:id/edit` and `POST /:id/regenerate` already returned a DOMAIN `code` on failure (`ARTIFACT_NOT_FOUND`, `ARTIFACT_EDIT_FAILED`, `ARTIFACT_REGEN_FAILED`, or whatever the engine's `ArtifactError` carried) — in the same field every other route now uses for the closed taxonomy (`not_found`, `unprocessable`, ...). The migration takes only the STATUS from the taxonomy (404 / 422, the same numbers as before) and keeps the domain code verbatim, so these two endpoints are the one place where `code` is not a taxonomy value. Replacing them would silently change a field external /v1 clients may read. Nothing in this repo reads them (the frontend does not). Pinned by `artifactsEnvelope.test.js` so it cannot change by accident.
