## What this pass implemented

### 1. E9 — canonical claims now feed beliefs (was: 0 links for E6-only owners)
`brain/reflectionV3/claimBeliefBridge.js` + wiring in `claimBeliefAdapter.js`.
First-person (`type='self'`, never a label), current, `fact` claims with a
curated target — the SAME vocabulary as the legacy fact bridge (organization,
profession, project, tech knowledge) — seed a belief through the Belief Engine
(`fact_bridge` source; engine dynamics decide confidence) and write the
`aqua_belief_claims` provenance link. If the belief already holds the value
(legacy lane saw the same sentence) the claim is **linked, not re-applied**.
Claims about other people, intents, history and uncurated predicates never
become beliefs. `claimWithEvidence` now returns `subjectType`.
- Unit: `claimBeliefBridge.test.js` 7/7. **Live:** `beliefLoop.live.test.js`
  7/7 — belief + link created, other-person claim excluded, replay writes no
  duplicate link, an employer change supersedes the claim and the belief
  follows with the old value versioned, owner isolation, purge removes links.

### 2. Claim lifecycle — a changed fact retires the old one, and only that
- **Cardinality is declared in the predicate registry** (`SINGLE_PER_SUBJECT`:
  works_at, role_is, located_in, reports_to, has_status, deadline_for,
  owned_by; inverses derive one-per-object: owns, employs, manages). Everything
  else is multi-valued — two `uses`/`prefers`/`member_of` values never conflict.
- S8 derives its single-valued sets from the registry (was hardcoded
  `['works_at']`, default off) and detects one-per-object changes ("Rohan owns
  X" vs "Kavya owns X").
- The E9 worker tells the policy when two claims are **registry-declared
  snapshots** of one fact; only then does rule 5 retire the older (superseded,
  `valid_to` closed, lifecycle row — history kept, L5). Polarity flips stay
  **disputed**; an explicit user correction still outranks extraction; intents
  and closed windows are not conflicts. **No global "newer wins".**
- Bugs found building it, all fixed: superseded claims were still contradicted
  (worker then threw "changes nothing" until DLQ); the policy parsed Postgres
  timestamps with `Date.parse(Date)`, dropping milliseconds so same-second turns
  tied and real changes stayed disputed; a return to an old value (A→B→A) either
  corroborated the superseded row or, with the same sentence, collided with the
  exact-dup unique index and the commit failed **silently**.
- Migration **0017**: the exact-dup guard applies to current claims only
  (superseded/archived rows stay as history and no longer block the present).
- `AQUA_E6_SINGLE_VALUED` default **on**, justified by a new gated eval;
  `off` is the rollback.
- Eval: `claim-lifecycle` (18 sequences, production S8 + production worker):
  **18/18, 0 false supersessions, 0 missed retirements, 0 wrong disputes**;
  under the old default 8 cases fail (bite). Baselined; its four error counts
  declared lower-is-better (undeclared, the gate would have called a rise an
  improvement). Unit `claimLifecycle.test.js` 6/6; **live
  `claimLifecycle.live.test.js` 8/8** (A→B→C, multi-valued, owner change,
  idempotent worker replay, return to an old value with the same sentence,
  past-tense question shows history marked "no longer current", owner isolation).

### 3. Natural references — "my company", "our launch", "that"
- `canonicalReadModel.findEntities`: **head-noun** anchoring ("our launch" →
  "Android launch") and **role nouns resolved through the user's own current
  relations** ("my company" → what the self `works_at`/`member_of`/`founded`;
  "my manager" → `reports_to`; "our office" → `located_in`), by entity type.
- Structured lane: when a question cue narrows the query, facts ABOUT the
  non-self anchored entity are still fetched.
- `conversationFocus.js`: per-conversation, bounded, TTL'd, purgeable memory of
  the previous turn's entity ids; used only for deictic questions; chat passes
  `conversationId`.
- Predicate cues are patterns, not literal phrases ("where do I work?" →
  `works_at`; "deep work" no longer matches employment).
- Superseded claims reached a past-tense context unmarked — now rendered "no
  longer current — past only" (the flag was dropped in two re-normalizations).
- Live `referenceResolution.live.test.js` 9/9 (including: a focus-only question
  resolves in the same conversation and resolves to nothing in another).
- **Write side (S6) unchanged:** possessive-role subjects ("our office moved…")
