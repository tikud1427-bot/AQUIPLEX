## What this pass changed

### E9 J3 — semantic consolidation is a durable scheduled job
- **Job:** `claim.consolidation.v1`, one per owner. Handler in
  `core/jobs/workerRuntime.js`; domain step in
  `brain/reflectionV3/consolidationWorker.js`.
- **Schedule:** the worker loop calls `scheduleConsolidation()` every
  `AQUA_CONSOLIDATION_INTERVAL_MS` (registered setting; default 10 min; `0`
  disables). It enqueues a job only for owners that actually have duplicate
  groups. The idempotency key is per owner per interval bucket, so any number
  of workers enqueue it once. Priority 200, so it never delays understanding
  or reflection.
- **Equivalence oracle:** S8's write-time structural identity applied after the
  fact: same subject, predicate, object (entity / normalised literal /
  quantity / unit / time), polarity, modality and validity window. No
  similarity threshold is invented (L14/L16). Disputed and stale claims are
  never merged.
  - **Why duplicates exist:** the 0017 index deduplicates on wording only.
    Concurrent turns, replays under a new extractor version, and backfill next
    to E6 can leave two current claims for one fact.
- **Survivor:** the existing planner (`semanticConsolidator.js`) and its rule:
  explicit user source > file > chat > inferred, then evidence count, then id.
- **Merge** (`worldModelRepository.consolidateClaimDuplicate`), one transaction:
  - Both rows are locked in id order (no deadlock) and re-verified under the
    lock. A pair that changed or was already merged returns `applied:false`
    (counted as `raced`).
  - **Non-destructive:** the absorbed claim is **archived**, never deleted, and
    can be reversed by a transition back.
  - **Provenance:** its evidence links and belief links are **added to the
    survivor**, and the archived claim keeps its own.
  - **Recorded as:** a lifecycle row (actor `e9:j3-consolidation`; reason names
    the survivor), a `merge` revision (`after.mergedInto`), and a `record`
    outbox event, `world-model.consolidation`, written published (never
    orphaned).
- **Retries / DLQ / observability:** retries and the dead-letter queue come
  from the existing queue (2^n backoff, 5 attempts → DLQ). Observable as a
  `job.run` span; `aqua_j3_{scheduled,runs,groups,merged,raced,failures,evidenceLinked}_total`
  (plus `aqua_worker_j3_*{process}` from worker snapshots); and per-kind queue
  depth, retries and DLQ via the existing `aqua_jobs_window` / DLQ metrics.
- **Tests:**
  - Unit 4/4: survivor rule, final-survivor collapse, raced pair counted,
    failure counted and rethrown, exposition.
  - **Live-PG 10/10** (`brain/tests/consolidation.live.test.js`):
    - concurrent turns create real duplicates;
    - scheduled once across repeated scheduling passes;
    - the job (via the real `runOneJob` claim → handler → complete) archives the
      duplicate, moves evidence, and writes lifecycle, merge revision and
      published outbox rows;
    - the next context shows the fact once;
    - re-run is a no-op;
    - every merge was made by a job of the same owner;
    - three concurrent jobs on one owner make exactly n−1 merges with no errors;
    - a failing job dead-letters through the real queue;
    - `/metrics` shows the counters.

### Revision voice — Prometheus counters
- **Counters** (`core/observability.js`), recorded in `Brain.revisionDirectiveForTurn`:
  - `aqua_revision_voice_considered_total`: candidate transitions examined.
  - `aqua_revision_voice_emitted_total`: revisions raised.
  - `aqua_revision_voice_suppressed_total{reason}`: candidates decided against
    (said-in-this-conversation, user-correction, no-longer-current,
    missing-statement, newer-chosen, lost-race).
  - `aqua_revision_voice_skipped_total{reason}`: turns that never selected
    (no-owner, flag-off, unsuitable-turn, no-candidates, error).
- **Cross-process:** every server instance now publishes its snapshot to
  `aqua_process_metrics` (role `server`, the existing 0020 table), and
  `/metrics` emits `aqua_servers_alive` and
  `aqua_server_revision_voice_*{process,…}`, so one scrape sees the voice
  across the fleet. Verified live by scraping the real `/health/metrics`.

### Defect found and fixed (L15, not flagged)
**Concurrent first turns for one owner lost a turn.** Both turns missed the
entity SELECT and both inserted. For the self entity, the second commit failed
on `aqua_entities_one_self_idx`, losing the whole turn; for other entity types
it silently created a duplicate entity (an L8 violation). Find-or-create is now
serialised per (owner, type, label) with a transaction-scoped advisory lock;
the 64-bit key is computed in JS. Found by the J3 live test, and proven by it.
The in-memory test harness stubs the lock (declared in `memoryPg.mjs`, as for
`pg_advisory_lock`).
