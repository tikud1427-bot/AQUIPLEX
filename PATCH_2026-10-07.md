# Patch 2026-10-07 — the loop, run on a real Postgres

Built on your latest upload (the 10-06 patch). Run `./apply-deletions.sh` after extracting: the two `before-pr` snapshots came back again.

The loop was run for real on Postgres 16 + pgvector for this patch: a user turn, understanding, claims in Postgres, the worker, context for the next question, a change of state, a correction. Six defects showed up that no fixture-backed test could see. Each is fixed, and each fix makes the new live test fail when it is reverted (eight mutations, all caught).

## 1. E6: every past score was measured on a prompt that contained the answers

Six of the eleven few-shot examples in `fixtures/extraction-prompt.v1.json` were verbatim `extraction-core` sentences. They included `negation-002` and `negation-016`, both negation-gate cases, plus modality, temporal and negative cases. Two more were near-copies, and rule 2 quoted a third.

**Every recorded E6 number (precision 0.92–1.00, recall 0.78–0.89, negation 0.70–1.00) is therefore an upper bound, not a measurement.** The fixture was edited on Sep 15, after the last full run on Sep 6, so a green gate on the next run would have been leakage.

- **Examples replaced.** The new examples are novel sentences covering the same constructs. The highest overlap with any eval sentence is now 0.27, down from 1.00.
- **Predicate meanings added.** Each predicate's meaning is rendered from `predicateRegistry.js`, so prompt and validator cannot disagree. Root cause of the one miss on every recorded run (`negation-012`, "I never learned Rust properly"): the prompt listed bare names, so the model read `habit_of` as "recurring habit". The dataset uses it for any activity, including learning and studying. No labels, cases or thresholds were changed.
- **Prompt version bumped.** `PROMPT_VERSION` is now `extract-v2`; it is part of the cache key, so v1 outputs cannot be served for the new prompt.
- **New test.** `extractionPromptContamination.test.js` reads the dataset itself and fails on any eval sentence, or near-copy (token Jaccard ≥ 0.5), anywhere in the prompt. It fails on the old prompt.

**Needs you.** Provider calls are blocked from my sandbox, so measure fresh:

```
node scripts/e6-shadow.mjs --category negation --repeat 5
node scripts/e6-shadow.mjs --repeat 3
```

Expect precision and recall to move too. The E6 gate is not passed until these say so.

## 2. First-person statements never reached the world model

With `AQUA_SELF_ENTITY=on`, "I am building X" came back `no-self-entity` and was dropped. The self node was only ever created as a side effect of conversation ingest, which in production runs in a different process from the durable worker that runs `understandTurn`.

Fix: `understandTurn` creates the self node itself. The call is idempotent and does nothing unless `AQUA_SELF_ENTITY=on`.

## 3. Every entity was stored as `concept`

The identity store view hands entities over with `kind`; the repository reads `type`. So people, organisations and the user's own self node were all written as `concept`, and `type='self'` (with the schema's one-self-per-owner index) never matched anything.

Fix: `understandTurn` passes `type`. The repository still owns the allowed set.

**Existing rows are not retyped.** Your production database may hold a `concept` row labelled "You". A new `self` row will be created next to it. Nothing is deleted (L5); merging the two is a one-off reconcile left for you to decide.

## 4. Questions anchored on no entity

`findEntities` checked whether an entity's label contained the **whole question** (`label ILIKE '%what is blocking the launch?%'`). Natural questions anchored on nothing, so the structured and graph lanes ran on predicate hints alone.

Fix: an entity now anchors when its label (or an alias) appears in the question as whole words. The old direction is kept for partial names.

**New self anchor.** First-person questions ("what am I building?") anchor on the owner's `type='self'` entity by type, never by label (L8). "You" addressed to Aqua does not anchor on the user.

## 5. The model received "• undefined" for every canonical claim

Canonical World-Model facts are built with `text`; the Context Engine read only `statement` (the shape of the older PIC store's facts). Retrieval found the right claims and the prompt said `undefined`. The lane label was also lost (`unknown`).

Fix: both shapes are read and lanes are preserved. Bug fix, not behind a flag (L15).

## 6. Every reflection job and every contradiction job failed on live Postgres

- **Reflection jobs.** `claimWithEvidence` ordered evidence by `e.created_at`; the column is `extracted_at`. `listEntities` and `getEntity` selected `created_at`/`updated_at`; entities have `first_seen_at`/`last_seen_at`. Every `claim.reflection.v1` job failed and retried; the claim-detail route ("why do you know this?") and the entity routes failed as well.
- **Contradiction jobs.** Claim ids were assigned only after S8, so every `claim.contradiction.detected` event carried `incomingClaimId: null`, and the contradiction worker throws when either id is missing. Contradiction resolution had never run on a real turn.

Fixed both. Checked on live Postgres: reflection jobs now complete, and a polarity flip produces an event with both ids that the worker processes.

**Your decision.** The contradiction policy marks both sides `disputed` ("Reliability is blocking the launch" vs "The reliability blocker is resolved"). The context then shows both as contested, which is honest. It is arguable that a later, explicit statement by the user about their own world should supersede (L20). I left the policy unchanged; it is a product call.

## 7. Running the battery wrote into your real database

`run-tests.mjs` sandboxed the data directory but not `DATABASE_URL`. Your `.env` is loaded by dotenv, so a local battery talked to your real Postgres: `e6TurnPath` enqueued real `understanding.turn.v1` jobs there. They are visible in a worker log as owners `u-obs`, `u-s6-wire` and `u1`.

- **Runner.** Tests now reach Postgres only through `AQUA_TEST_DATABASE_URL` (see `src/core/db/testDatabaseEnv.js`); otherwise `DATABASE_URL` is forced empty.
- **Clean up.** If you ran the battery against production, delete those test-owner rows from `aqua_jobs`.

## New live test: `src/brain/tests/cognitiveLoop.live.test.js`

It exercises the production functions throughout; the only stand-in is a scripted extraction model, so it proves wiring, not extraction quality. Eight steps:

1. Turns become canonical claims, first person included.
2. Replaying the same turn writes nothing new.
3. The model is handed real claim text, and a natural question anchors on the entity it names.
4. First-person questions anchor on the user.
5. Another owner sees, finds and corrects nothing.
6. A later turn produces a contradiction the worker can act on; the new state reaches the context.
7. Correction: the old claim is superseded with a pointer to its successor, has evidence and an audit row, and the next context shows the corrected state only.
8. Every canonical read the product calls runs against the real schema.

Without a database it reports one visible SKIP. To run it:

```
DATABASE_URL=postgresql://…/aqua_test npm run db:migrate
AQUA_TEST_DATABASE_URL=postgresql://…/aqua_test npm test
```

## Still open (measured, not fixed)

- **Blocker missing from "What should I focus on next?"** The context returns what you're building and the launch plan, but not the blocker: the launch entity is not connected to the self node, and the context engine has no slot that pulls blockers for focus questions. This is E8 slot work.
- **Embedding jobs retry forever without Gemini keys.** That is correct per L13, but they never dead-letter, so a missing key shows only as queue depth.
- **Server and worker keep separate id caches.** Each process caches the id map, and `[DB] store write failed: changed underneath this instance` appears under load. The self fix sidesteps this for the self node only; other entities can still diverge. This is E3 work.
