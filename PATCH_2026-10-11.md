## A. IMPLEMENTATION STATUS

### Gap 1 — possessive / implicit subject resolution (write side): PASS
`brain/understanding/referenceResolver.js` (new S6½, before the minter) plus
three owner-scoped reads in `canonicalReadModel.js`. It applies only to claim
ends the minter refuses (`isMintableSurface` false), so every previously
mintable surface behaves exactly as before.
- `my/our company|employer|startup|firm|org…` → the object of the user's
  current `works_at` / `member_of` / `founded` (self found **by entity type**,
  never by label, L8). `my manager|boss` → `reports_to`. `our team|group` → `member_of`.
- `it/they/that/…` → non-self entities claimed in the **previous turn of the same conversation**.
- `the/our <…> launch` → the one entity whose label ends with that head noun.
- **Exactly one candidate** → resolved. The minter reuses the existing id, and
  the evidence locator records `references: [{surface, method, resolvedTo, via}]` (L4).
- **Several** → not committed; `blockedBy: subject:ambiguous-reference`. Uncertainty is kept, never guessed.
- **None** → not committed (same as before).
- **Location roles** (`our office`, `my city`) are never resolved: mapping
  "the office" onto the user's city would be a false fact.
- Counted: `aqua_e6_ref_resolved|ambiguous|unresolved` (server) and `aqua_worker_e6_ref*` (workers).
- Tests: unit 5/5; **live-PG 8/8**: first-person possessive, collective (two
  teams → ambiguous, nothing written), unresolved manager, location never
  resolved, cross-turn pronoun, head noun, owner isolation, provenance in the evidence row.

### Gap 2 — revision voice: PASS, **canonical voice enabled by default**
What was missing: the voice read only the legacy PIC ledger, so it never saw a
canonical change (E9 supersession or dispute). Its watermark was a
per-process JSON file, so two server processes could each raise the same
revision, and a restart could repeat one.
Built:
- `brain/reflectionV3/canonicalRevisionVoice.js` (pure selection + wording),
  `canonicalReadModel.revisionVoiceCandidates`, migration **0021**
  `aqua_revision_voice_state`, and `worldModelRepository.advanceRevisionVoice`
  (compare-and-set, strictly forward on `(created_at, transition_id)`).
- `Brain.revisionDirectiveForTurn` (async), called once per turn by `chat.js`.
  Raised: an unsettled **dispute** (asked as "which is current"). Also a
  **policy supersession from an earlier conversation**. Never raised: user
  corrections (same signals as policy rule 1); a change from **this**
  conversation (echo); a transition no longer true (e.g. a dispute later
  overtaken); working turns, which neither raise nor consume it.
- Never invents: it quotes only stored `statement_text`, whitespace-collapsed
  and capped at 160 characters. A dispute's counterpart must itself still be
  `disputed`. That condition was a real bug found by the eval: the first
  version paired a disputed claim with any newer current claim.
- **Evaluation (L14):** `eval/suites/revision-voice.suite.mjs`, 18 cases run
  through the production S8 detector, contradiction worker and selection.
  Result 18/18; wrong / missed / wrong-content / invented / repeat raises all 0.
  Baseline `revision-voice.v1.json`, gated (all five error metrics lower-is-better).
  **Bite verified by mutation:** removing the echo rule, the correction rule,
  newest-first ordering or the stale-row rule each fails the gate.
- **Live-PG 9/9:** raised once across conversations; echo suppressed;
  dispute; correction never raised; working turn does not consume; **five
  concurrent callers raise exactly once**; flag off; isolation; purge.
- **Decision:** `AQUA_REVISION_VOICE` default → canonical voice ON. The
  legacy-ledger voice was never evaluated this way, so it stays opt-in (`=on`).
  `=off` is the rollback. Reported as `revisionVoice=canonical|canonical+legacy|off`.
- **Not measured:** whether the answer model phrases the question well. That
  needs a provider (Section C).

### Gap 3 — context seat quality: PASS (from the earlier part of this pass)
Relative floor (≥ 0.3 × top score) plus a relevance-backed gate: when any
candidate has a relevance signal (semantic ≥ 0.3, graph hop, focus/project/goal
continuity, slot, structured or graph lane), unbacked ones are dropped
(`no-relevance-signal`). context-core re-baselined (noise lines 18). Tests
10/10. Residual noise is an abstention question, not seat filling (the
"Entity: You" removal measured worse, 18 → 19, in three configurations).

### Gap 4 — outbox entity/edge events: PASS
`core/worldModel/outboxEvents.js` classifies every event. **Dispatch**
(consumer required; enters the queue): claim.created / corroborated /
contradicted / superseded / stale / contradiction.detected /
embedding.requested. **Record** (audit only; written `published`):
entity.created / observed, edge.created, event.created, world-model.lifecycle /
correction / revision. Writing an unregistered type throws. A source scan
proves the dispatch set equals what the dispatcher consumes. Migration **0019**
published the backlog of record events on the test DB (264 entity.created,
181 edge.created, 30 lifecycle). It also **found and fixed a wiring gap**: a
claim becoming disputed/stale emitted `world-model.lifecycle` (unconsumed), so
it never reached reflection (J2). It now emits `claim.contradicted` / `claim.stale`.
Durability, retries, DLQ, replay and isolation are the existing queue's
(E4, tested). Live tests 5/5.

### Gap 5 — worker metrics on the server's /metrics: PASS
Migration **0020** `aqua_process_metrics`. Each worker upserts its snapshot
every 15 s (final tick on shutdown); `/metrics` emits `aqua_workers_alive`,
`aqua_worker_snapshot_age_seconds` and per-process span, error, cost and E6
series. A dead worker ages out after 2 minutes. No in-memory sync, nothing
synthesised. Alert `AquaNoLiveWorkers` (11 rules, CI-checked against emitted
metrics). Live test: a real job runs, two live and one dead snapshot, real
`/health/metrics` scraped.

### Part 7 — external backends now activate from environment: PASS (local boundary)
- `core/telemetryExport.js`: **OTLP/HTTP JSON** span exporter
  (`OTEL_EXPORTER_OTLP_ENDPOINT` / `_TRACES_ENDPOINT` / `_HEADERS`,
  `OTEL_SERVICE_NAME`). Batched, bounded queue, timeout, flushed on SIGTERM.
  Plus an **error webhook** (`AQUA_ERROR_WEBHOOK_URL`, `_TOKEN`). Wired in the
  server (`aqua/router.js`) and the worker; the boot line names what is active.
  Tested against a real local HTTP receiver (5/5), checking path, headers,
  OTLP shape, ids, status, scrubbing, and that a failing collector only
  increments a counter.
- `utils/rateLimitStore.js`: **Redis backend** (`AQUA_RATE_LIMIT_REDIS_URL`,
  redis:// or rediss://, AUTH, db). One atomic Lua script per hit; RESP2 over
  net/tls, no dependency. An unreachable Redis falls back to per-process
  counting, with a warning and a count. **Live against Redis 7 (7/7)**,
  through the real express-rate-limit: two stores (two processes) share one
  window (200, 200, 200, 429, 429), plus TTL, undo floor and reset.
- Not verified against a specific vendor (collector, tracker, managed Redis).
  Configuration is in `docs/OBSERVABILITY.md` and `.env.example`.

## E. PRODUCT / ONTOLOGY DECISIONS REQUIRED
1. **Location-role references** ("our office moved to Pune"): resolving them
   needs an `office_of` / `located_in` distinction in the ontology. Today they
   are deliberately not committed.

   should be opt-in per user, is a product call. The legacy voice stays off.

   candidate is relevant (the residual context-core noise).

   per the 10-10 decision, pending a product answer.
