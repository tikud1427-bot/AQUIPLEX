# Pre-registration — World Model value on long histories (Lift v4)

Registered 2026-10-12, **before any v4 answer exists**. Both earlier v4 runs (2026-10-11/12) died during
ingest (host sleep; a user-mode `SetSuspendState` at 14:36:21 on 10-12) and produced no answers or
partial results. Nobody has seen a v4 answer, grade or per-question output.

## Question

When a user's history is longer than the production conversation window, does Aqua's canonical World
Model context, alone or combined with retrieval, answer questions about that user better than
(a) the production history window and (b) plain BM25 retrieval at the same context size?

## Conditions

| Condition | Context given to the answerer |
|---|---|
| `history` | production conversation window: newest turns up to 12,000 tokens (`tokenManager` rule) |
| `memory` | BM25 top-8 past turns |
| `memoryMatched` | BM25 turns up to the World Model block's size for that question |
| `worldModel` | the production canonical context (`Brain.assembleContextAsync`, canonical lanes only) |
| `hybrid` | the World Model block unchanged, plus exactly the `memoryMatched` turns (`liftCore.hybridContext`). Total context is about 2× `worldModel`, which is stated here, not hidden. |

## Primary endpoint and decision rule

Primary group: **long** personas. Δ(A,B) = clustered mean correctness of A minus B, with 95% CI [lo, hi].
F(X) = fabrication rate of X on long personas.

Evaluated in this order. The first rule that holds is the decision.

1. **KEEP.** For C ∈ {worldModel, hybrid}: Δ(C, history) ≥ +0.10 **and** lo > 0 **and** F(C) ≤ F(memoryMatched).
   If both qualify, choose the larger Δ; on a tie, choose `worldModel` (smaller context).
   → Keep the World Model and take C's context assembly into a user beta.
2. **STOP.** For both C: Δ(C, history) has hi < 0.
   → Stop investing in the World Model as answer context; serve history window + BM25.
3. **SIMPLIFY.** For both C: Δ(C, memoryMatched) has lo ≤ 0.
   → Keep canonical claims only for state tracking (current values, supersession, provenance).
   Retrieval for answers becomes BM25 + the history window.
4. **INCONCLUSIVE.** Otherwise. No capability claim. Next step: a human-authored set and more personas.

Short personas, stale rate, unknown honesty, cost and latency are reported. They do not change the decision.

## Validity gates (checked before the decision is read)

- Judge errors ≤ 3% of graded units. Otherwise re-judge only, with the same judge and nothing else changed.
- E6 extraction errors ≤ 10% of ingested turns. Otherwise the run is invalid (infrastructure): rerun from
  scratch on a fresh database with the identical command, and report both runs.
- A crash invalidates the run the same way. There is no resuming across code or configuration changes,
  and no second configuration chosen after seeing results.

## Run discipline

- No code changes in the snapshot during the run.
- No inspection of per-question answers or grades until the final JSON is written and the decision has
  been recorded against this document.
- v4 stays held out: no product fix may be motivated by a v4 question. After this run, v4 is spent for
  tuning purposes.

## Known limitations, stated in advance

- v4 was written by an isolated AI agent of the same model family as the system's builders. It is
  synthetic and not human-independent.
- Only 4 long personas. The CI resamples questions, not personas, so it understates persona-level
  variance. Effects under about 10 points are likely to come out INCONCLUSIVE.
- The answerer is a free-tier 20B model and the prompt is the harness template, not the production
  system prompt. This measures context quality, not the shipped product turn.
- **Synthetic benchmark results are not evidence of real-user value or traction.**

## Command (run from the snapshot's `aqua/`)

```
AQUA_TEST_DATABASE_URL=postgresql://aqua:aqua@localhost:55432/aqua_v4_prereg \
node scripts/world-model-lift-live.mjs \
  --datasets eval/lift/world-model-lift-heldout.v4.json \
  --conditions history,memoryMatched,memory,worldModel,hybrid --history-tokens 12000 \
  --repeat 2 --answer-provider nvidia --e6-provider nvidia --e6-model openai/gpt-oss-20b \
  --concurrency 4 --ingest-concurrency 4 --keep \
  --prereg eval/lift/PREREG-v4-2026-10-12.md --json eval/out/lift-v4.prereg.json
```

The output records this file's sha256 and the dataset's sha256.
