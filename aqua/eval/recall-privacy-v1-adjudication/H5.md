# recall-privacy-v1 · H5: adjudication of a test-design timing error

**Status:** a test-design defect, not a privacy failure. The frozen package (`aqua/eval/recall-privacy-v1/`) is **not** modified. This note sits outside it and is not covered by its manifest.

## What H5 checks
"A vector made by the previous code from a masked passage is never used and is replaced."

The passage is `I have asthma. We are building an app for runners.`. The sibling's product framing ("app") masked the health sentence from the old whole-passage check, so the previous code embedded the full text.

| Step | Action | Expectation |
|---|---|---|
| 1 | `plantVector`: store the vector the way the previous code did (full text and its hash) | — |
| 2 | `ask "Do I have asthma?"` | nothing quoted; the provider never receives "asthma" |
| 3 | `index` | the provider receives `We are building an app for runners.` and not "asthma" |

## Result
- Steps 1 and 2 pass.
- Step 3 fails with `sent: []`: nothing was sent at step 3.

## Why the expectation was wrong
- **Where the replacement really happens:** `recallForTurn` starts a fire-and-forget indexing pass at the end of each semantic turn (`indexRecallUnits`). The step-2 turn ran that pass and found the planted vector's hash didn't match the passage's eligible text, so it re-embedded the passage. Only the eligible sentence was sent.
- **Why step 3 sent nothing:** by step 3 the vector was already current.
- **The flaw in the test:** it assumed the replacement would happen at the explicit step-3 index call. It happens one step earlier.
- **Why the grader missed it:** it captures sent text per step, including each step's background index pass. So the eligible-text send was recorded under step 2, where H5 has no `sentIncludes` expectation.

## Evidence that the property holds
This is an offline reproduction, with the same fake transport and placeholder key as the grader, network tripwired (0 attempts). It used the same history, the same planted vector, and one turn of `Do I have asthma?`:

| Observation | Value |
|---|---|
| quoted | `[]` |
| mode | `ranked` (no meaning score used) |
| `stats.semantic.queryWithheld` | `true`: the wholly sensitive question was never embedded |
| texts sent during that turn, including its background index | the 10 neutral fillers and `We are building an app for runners.`; **never "asthma"** |
| stored vector for the passage afterwards | matches the hash of `We are building an app for runners.` only |
| old full-text hash still present | `false` |

So within the first turn:
- the old vector is never used: there's no meaning score, nothing is quoted, and the read side rejects the hash mismatch;
- it is replaced by a vector of the eligible sentence only;
- no health text reaches the provider.

The same property is also covered, independent of step timing, by `src/memory/tests/retrievalPrivacy.test.js`, specifically "per-sentence embedding" and "forgetting AFTER indexing".

## Disposition
- The frozen result stays **20/21**, reported as is. H5 is adjudicated **pass on the property, fail on a test-timing assumption**.
- A future v2 of the test set should check H5's replacement at the turn that triggers it, rather than at a later explicit index step.
